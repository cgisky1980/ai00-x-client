# 智能路由分类器速度报告

日期：2026-08-21
测试环境：RTX 2080 Ti (22GB) / rwkv7-g1i-2.9b.int8 / router_head.json (2560→256→4)
方法：真实引擎完整链路（tokenize → 零状态 prefill → mean-hidden → MLP 头），每桶 50 次采样（前 3 次预热丢弃），共 250 次有效采样。

## 一、核心结论

**单次分类延迟：p50 = 79ms，p95 = 81ms，avg = 77ms**（250 次采样）
- 路由超时配置 3000ms，p95 仅占预算 **2.7%**，超时回落实际不会触发
- 相比旧 logits 方案（avg 1056ms）**提速 13.7 倍**
- 对话基线：本机 decode 17.7ms/token，即分类开销 ≈ **4.4 个 token 的生成时间**，相对一次完整回答（数百 token）可忽略

## 二、按请求长度分桶

| 桶 | 实际 tokens | min(ms) | p50(ms) | p95(ms) | avg(ms) |
|---|---|---|---|---|---|
| 短 | 16 | 69.5 | 70.7 | 72.6 | 71.0 |
| 中 | 64 | 73.0 | 74.3 | 75.5 | 74.4 |
| 标准 | 128 | 77.7 | 79.1 | 80.2 | 79.2 |
| 截断上限 | 128 | 78.1 | 79.4 | 81.0 | 79.5 |
| 超长(截断到128) | 128 | 78.4 | 80.1 | 80.9 | 80.0 |

**延迟对长度几乎不敏感**（16→128 token 仅 +12%）：seq 路径 GEMM 的 M 维按 256 对齐（m_pad），16/64/128 token 的矩阵规模相同；增量主要来自 [T,C] 下载与逐 token elementwise 算子。**用户无论发多长的请求，分类开销都稳定在 ~80ms。**

## 三、阶段拆解（128 token 请求，50 次平均）

| 阶段 | 耗时 | 占比 | 说明 |
|---|---|---|---|
| tokenize | 0.01 ms | 0.0% | CPU，可忽略 |
| state_load | 4.60 ms | 5.8% | 零状态快照恢复（~10MB 上传） |
| prefill + 下载 | 74.27 ms | **93.8%** | 32 层 GEMM + [T,C] mean pooling |
| MLP 头 | 0.32 ms | 0.4% | 2560×256 matmul + softmax，CPU 即可 |
| **合计** | **79.2 ms** | 100% | |

瓶颈明确：**93.8% 在 GPU prefill**，分类头本身 0.3ms 近乎免费。

## 四、冷启动与热状态

| 场景 | 延迟 |
|---|---|
| 冷启动（新 T 长度，含 seq 缓冲重建） | 79 ms |
| 热状态（同 T 长度复用） | 80 ms |

**冷热几乎无差**：本次修复 `clear_cache` 后 CUDA kernel 跨 T 复用，新长度请求仅需重建缓冲（显存分配，亚毫秒级）。用户每个新请求长度都是"冷"的，但代价可忽略。
（注：进程首次分类前的一次性 kernel 编译约 2 秒，仅发生在模型加载后第一条请求，生产中由启动预加载吸收。）

## 五、吞吐与一次性开销

- 连续吞吐：**12.4 次/秒**（80.4 ms/次，200 次连跑）
- 模型加载（一次性，启动预加载）：13.2 s
- 日常使用（对话间歇请求）：每次对话仅第一条消息触发分类（后续轮次 sticky tier 兜底），用户感知 ≈ 80ms 的首字延迟增量

## 六、优化空间（当前未做，按收益排序）

1. **前缀分桶复用**（论文 albatross 路径）：请求按长度分桶 padding 后 batch 提取，吞吐可翻倍以上——仅批量场景有价值，当前单请求交互模式收益小
2. **m_pad 降档**：GEMM M 维按 256 对齐，短请求（16 tok）实际算的是 256 行矩阵；按 64/128 分档对齐可将短请求压到 ~40ms
3. **state_load 增量化**：零状态全量恢复 4.6ms；可用"分类专用 state 只 reset 不重传"消除

## 七、结论

80ms 的分类开销相对「本地 RWKV 生成一条 R0/R1 回答（数秒）」或「云端 API 首 token（500ms+）」均可忽略，且 R0/R1 路由到本地模型本身节省的时间远大于分类成本。速度达标，无优化必要性。
